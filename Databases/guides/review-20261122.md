## Проверка

Все 15 установленных runtimes прошли общий Basic4: LA-RPQ, rpqmatrix,
rpqmatrixGB, Pathrex, Ring, DuckDB, Kuzu, Jena, PostgreSQL, MillenniumDB,
Blazegraph, Virtuoso, Neo4j, Memgraph, FalkorDB.

- Smoke: **64 совпавших query records** — 8 у Pathrex (два режима), по 4 у остальных.
- Benchmark: **15/15 completed**, четыре запроса, **4 измерения + 1 прогрев**,
  **240 основных samples**. Проверены ответы и число выборок. Это интеграционная
  проверка интерфейсов, не новая публикация сравнительной производительности.
- Пять регрессионных тестов проходят в обычном Python и с `-O`.
- Те же тесты проходят в отдельном checkout ветки конкурентов без данных
  и инициализированных submodules: справка и unit-проверки не требуют их.
- Общий config-runner прошёл dry-run для `pathrex-opt`.
- Для сохранённого текущего Pathrex `9aee0d5` выполнены native-linked
  release build и тесты: **173 passed, 4 ignored**, `cargo fmt --check` проходит.
- Rust-only Clippy с `-D warnings` прошёл с `DOCS_RS=1`; native повторно
  для линтера не собирался. Настоящие native build/tests проверены отдельно выше.
- Проверены URL закреплённых Jena/Blazegraph artifacts: оба доступны (HTTP 200).
  Docker использует сохранённые digest, wheels — версии requirements.

[Компактные результаты проверки](review-20261122.json). Полные логи и сырые
данные оставлены в `Results/competitor-review-20261122/` (machine-local).
Исторические `smoke-results.*`, `runtime-lock.json` и benchmark-данные не
переписывались новыми результатами.

Важно: это проверка **установленных бинарных поставок и адаптеров**. Она не
означает, что все 15 submodule source trees заново собраны с нуля. Source pins,
Docker/JAR/wheel versions и фактические executable hashes — разные сведения.
Свежий Pathrex тестировался на исследовательской ревизии; отдельная ветка
сохраняет опубликованный базовый pin, не подменяет его неопубликованным commit.

## Что готово для сервера и что ещё ограничено

Подготовка и запуск Basic4 описаны в [общем гайде](README.md), native build —
в [build-native.md](build-native.md), повторные измерения — в [benchmark.md](benchmark.md).
Для нового сервера отдельно нужны source N3 или согласованные prepared inputs:
датасеты и binaries не хранятся в Git. Bootstrap создаёт отсутствующие матрицы.

Следующие ограничения существуют и явно описаны; они не исправлялись изменением
семантики запроса или исключением неудобных ответов из проверки:

1. `smoke_250k.py` / `benchmark_all.py` привязаны к общему 250k fixture.
   `prepare_rdf.py` преобразует новые графы, но не является универсальным
   компилятором запросов/runner для всех 15 систем на любом датасете.
2. У Cypher-поставок нет общего adapter для compound RPQ; Neo4j WALK/edge-reuse
   и глубина Kuzu требуют отдельной проверки. Basic4 выбран в общем подмножестве.
3. Pathrex CLI считает targets, матричные baseline — пары. Нельзя проверять
   any-con/any-any прямым сравнением этих чисел. Расширенный workload20 имеет
   известные gaps и не объявляется полностью поддержанным.
4. Границы времени различаются: native solver, embedded execution/fetch,
   JVM parse/execute/fetch, сетевой roundtrip. Номинальный OMP=2 не доказывает
   одинаковое фактическое число потоков; Docker quota и native affinity различаются.
   Для научного сравнения на арендованном сервере нужен единый согласованный протокол.
5. Предложения по замыканиям, диагонали, семплированию и стоимости DAG остаются
   отдельным треком оптимизатора. Это ревью их не реализует.
